# GPUIデスクトップ検証アプリ

Windowsを製品対象とする薄いネイティブUI。共通コアと実データを使う最初の縦断実装で、最終デザインではない。開発用Linux環境でもビルドできる。

```sh
cargo run -p ultratasks-desktop
cargo run -p ultratasks-desktop -- --database ./local/demo.db --timezone Asia/Tokyo
cargo run -p ultratasks-desktop -- --reduce-motion
```

標準の保存先はOSのアプリケーションデータフォルダー。既存のデータを自動でサンプルへ置き換えない。`--database`で別のDBを指定できる。指定がない場合、表示タイムゾーンはOSから取得し、取得できなければUTCになる。画面上部に実際のタイムゾーンを表示する。

## 操作

1. タスク名を入力し、追加ボタンまたはEnterで保存する。
2. タスク名を選ぶと、名前の変更・削除・時間の割り当てができる。
3. 開始時刻を`HH:MM`、所要時間を分数で入力する。表示中の日付へ作業枠を作る。
4. 作業枠の「+30分」で開始・終了を30分後へ移し、「解除」で作業枠だけを外す。
5. 完了・元に戻す・やり直すを試し、再起動して保存を確認する。
6. 「動き: ON/OFF」または起動引数で、同じ操作のアニメーション有無を比較する。

時刻入力は夏時間で存在しない／二通りになる時刻を拒否する。所要時間は実際に経過する時間として扱い、日跨ぎを許す。TaskとTimeBlockは別データなので、作業枠の解除でTaskは消えない。

## 編集する場所

| ファイル | 役割 |
| --- | --- |
| `src/views/` | layout・task_list・detail・agendaの各部品と、どの操作APIを呼ぶか |
| `src/presentation.rs` | 時刻入力などの表示用変換 |
| `src/theme.rs` | リポジトリのデザイントークンをGPUIへ対応付ける唯一の場所 |
| `src/backend.rs` | SQLiteを所有するワーカースレッドと画面へのスナップショット |
| `src/main.rs` | 起動引数・保存先・ウィンドウ生成 |

デザイン設定はルートの`design/tokens.json`と`design/palettes.json`をビルド時に読み込む。フェードと位置補間の時間もそこから取得する。予定カードの位置補間は更新時に12px移動させる性能確認用の仮動作であり、ドラッグによる時間軸編集ではない。GPUIの有限時間アニメーションを使い、独自の常時フレームループは持たない。

SQLiteの作業は専用スレッドへ送る。保存中の入力・重複操作・通常のウィンドウ終了を抑制し、失敗時には入力を残す。タスクは1ページ1000件までで仮想リスト表示し、前後ページと明示的な検索に対応する。日別の作業枠・イベントは各1000件を上限にし、上限に達した場合は画面で通知する。

## ネイティブ依存

GPUI Kit `=0.9.0`（上流tagのcommit: `7591a35eced761e3613c01e71ff04c10129dae1a`）を使用し、互換GPUI snapshotはKit経由で固定する。WebViewやJavaScriptシェルは使用しない。GPUI KitのソフトウェアライセンスはApache-2.0。

Linuxでのビルドには、C/C++コンパイラー、fontconfig、freetype、Wayland、xkbcommon/X11、ALSA等の開発ライブラリが必要になる。起動にはX11またはWaylandセッションとVulkan等の対応描画環境が必要。実際の検証結果はルートの開発記録を参照する。

## この段階の範囲

コアの予定は繰り返しを展開して日別一覧で表示する。予定・所属先・期限・繰り返し規則の編集や同期・AIの設定画面は、この仮UIへまだ接続していない。共通APIとCLIで操作できる。Windows通知は保存後と定期的に再照合し、失敗は保存失敗と区別して表示する。`--disable-notifications`でこの端末の予約を取り消す。OS権限・常駐処理の条件は[通知仕様](../../docs/notifications.md)を参照する。

IME入力部品はGPUI Kitを再利用し、Enter処理には未確定文字の確認を追加している。日本語IME実機・WindowsのNarrator・AndroidのTalkBackの合格を、このコードがあるだけで主張しない。Linuxソフトウェア描画によるスモークテストは、Windows／Android実機の性能測定とは区別する。
