# UIの方向性と制作手順

2026-11-09 / 初期提案。以下の数値と画面構成は比較のための出発点であり、ユーザーが承認した完成デザインではない。

## 目指す体験

「今日やること」と「使える時間」が同じ画面で分かる。タスクを時間軸に置くと作業枠になり、元のタスクとつながったまま動く。朝の計画、作業中の見直し、終わった後の整理を短い操作で行える。

見た目は静かなグラファイトを第一案とする。Radix Slateで面と文字の階層を作り、Blueを操作と選択、Jade・Amber・Tomatoを予定の分類の候補に使う。分類は色だけで識別させず、タイトルやアイコンも添える。ライトテーマも同じ意味のトークンを持つ。予定のカテゴリ色は、現在のトークンにある成功・警告・エラーの状態色とは別の用途として実装時に定義する。赤い予定をエラーとして読ませない。

## 最初に磨く操作

1. ショートカットまたは追加ボタンから入力する。IME変換確定と送信を区別する。
2. タスクを時間軸へ移し、スナップする時刻と所要時間を見てから確定する。時刻指定メニューでも同じ操作ができる。
3. 完了しても読んでいた位置を見失わない。Undoで戻せる。
4. 予定を移動する。ドラッグ中の仮表示、キャンセル、確定を区別する。
5. キーボードだけで一覧・入力・日付選択を行い、閉じた後は元の位置にフォーカスが戻る。

## 部品と視覚のルール

- GPUI Kitの入力・メニュー・フォーカスの振る舞いを評価し、外観をトークンで統一する。
- 通常の本文は14 logical px、行高20を初期値にする。日本語では実描画を見て調整する。補助情報も文字拡大に追従させる。
- Windowsは32〜36pxのコンパクトな操作密度を検討する。Androidの主要タップ領域は48dpを初期基準にし、GPUI座標とOSの表示倍率の対応を実機で確認する。
- 角丸は用途別に少数へ絞る。情報を並べるためだけのカードや、常時動く装飾を増やさない。
- 操作結果は即座に状態へ反映する。短い色変化・移動補間を使い、アニメーション終了まで入力を止めない。動きを減らす設定では移動補間を省く。
- OSの日本語フォントを第一候補とし、フォントファイルの同梱は別途選定・ライセンス確認する。

## 制作の順序と完了条件

| 段階 | 残すもの | 次へ進める条件 |
| --- | --- | --- |
| 基準作り | OSS比較、色・アイコン・出典、コンセプト案 | どの部分を再利用し、どの操作で差を出すか説明できる |
| 技術スパイク | WindowsとAndroidの最小画面、依存固定、操作録画 | 日本語入力・スクロール・ライフサイクル・WebViewなしの成立性を確認 |
| 部品ギャラリー | 通常・focus・disabled・error・long text等を同じ画面で比較 | 入力、フォーカス、配色、文字拡大、読み上げを検証 |
| 今日の縦断実装 | 追加→時間割り当て→完了→Undo→再起動 | 操作とローカル保存が一連で成立し、空・失敗・大量データでも崩れない |
| カレンダー拡張 | 週表示、重複、終日、日跨ぎ、繰り返し仕様 | 時間とデータの意味を保ち、ドラッグ以外の操作でも使える |

ユーザーに画面と操作録画を見せ、違和感を次の反復へ反映する。自動スクリーンショット比較は意図しない崩れの検知に使い、美しさの承認を代行させない。

## 性能の初期目標

数字は達成値ではなく、基準端末を決めて調整する目標。release buildで、起動時間、入力から描画までの遅延、スクロールのp95 / p99フレーム時間、アイドルCPU・メモリを記録する。60Hzでは1フレーム16.7ms、120Hzでは8.3msを予算の目安にする。1万件のタスクでも全件描画しない構成を検証する。

既存の良いOSSを使うことで、UltraTasks固有のタスクと時間のつながり、キャンセル・Undo、操作中の視線とフォーカスの保持に時間を使う。
